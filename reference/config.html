Config — bupha.yaml / bupha.toml ​

Both formats are permanent. bupha.yaml/.yml are preferred over bupha.toml at each search step — --config, $BUPHA_CONFIG, ./bupha.*, ~/.config/bupha/bupha.* — and an explicit .toml path still parses as TOML. Fields below are spelled in TOML; in YAML the same names nest under : maps ([[repo]] → repos:/repo: list, [repo.runner] → runner: map). Local-path fields (dir, base, sccache_conf, cli_source, audit.path, telemetry.path, attest.dir, cache.conf) expand a leading ~/ to $HOME at load in both formats. See examples/bupha.toml.example and examples/bupha.yaml.example.

In a deployed tamias bundle this file is generated by tamias-driver-bupha deploy (fleet.toml + provider.ingress → ~/.config/bupha/bundles/<name>.toml) and consumed by the driver's host and worker verbs — watcher engine and ci-job entity consumer. The bupha CLI's --config/doctor verbs are the dev-harness path (ADR-0006: no user-facing CLI).

[[repo]] ​

fieldtyperequirednotes
namestringrequiredrepository.full_name in the webhook payload ("owner/name") — also the status target repo.
dirpathrequiredClone to fetch + create detached worktrees from. A leading ~/ expands to $HOME at load.
branchstringoptionalThe ref to watch (e.g. "refs/heads/main").
status_repostringoptionalStatus repo override (defaults to name).
runnerRunnerCfgoptionalPer-repo runner override — a full [repo.runner] table replaces the global [runner] for this repo.
queue`"latest""all"`optional
secret_envstringoptionalPer-repo webhook-secret env var — a NAME resolved like trigger.secret_env (its fallback). Lets each repo's hook be managed and rotated independently of the other watched repos.
runs_onlistoptionalFleet routing: labels a claiming worker must carry (e.g. ["arch=arm64"]). Empty = any worker. Per-repo arch pinning — same-push multi-arch matrix is future work.
retryu32optionalFailed runs re-enqueue at the back this many times (0..3, ADR-0002 §3). 0 = today's behavior. A failed sha may retry — a superseded or claim-lost one may not.
sturnbooloptionalOpt this repo into the [trigger.sturn] WAL poller — its jobs enqueue on Op::Snapshot events found under refs/sturn/wal/* in dir, no webhook needed. Repo-level: every job inherits it (branch filters still apply).
eventslistoptionalSource event kinds this repo runs on — "push" and/or "pull_request" (GitHub webhook deliveries). Empty = ["push"] (today's behavior). Repo-level: every job inherits it.
jobsVec<JobEntry>optionalPipelines within this repo ([[repo.jobs]]). Each job gets its own branch filter, queue policy, runner and status context — one webhook feeds them all. Empty = the repo itself is its single implicit pipeline.

fieldtyperequirednotes

[worker] ​

fieldtyperequirednotes
labelslistoptionalLabels this box carries (e.g. ["arch=arm64"]). A job whose runs_on requirements are all satisfied here is claimable; unlabeled jobs are claimable by anyone.
nodestringoptionalHypha/peregrin node base URL for the entity-plane worker (tamias-driver-bupha worker, P-002) — e.g. http://127.0.0.1:18787. Absent = the entity worker has no node to poll (the retired redis pull-queue path is gone — T-049).
node_token_envstringoptionalEnv-var NAME holding the node's bearer credential — resolved through the secret chain (env → cuora → ~/.config/bupha/env), the same rule as token_env/ secret_env: the config stores the NAME, never the value. peregrin pair/hypha pair mints the token; store it under this name (e.g. PEREGRIN_TOKEN). Absent = unauthenticated calls (dev nodes).
events_urlstringoptionalFull URL the worker POSTs ci.job.completed to — the /api/events/inject route of the campaign host (e.g. http://127.0.0.1:29173/api/events/inject for campaign serve). Absent = {node}/api/events/inject — the entity node's own ingest, which fans out to kind="campaign" entities, NOT to campaign serve supervised campaigns. Set this when campaigns run under campaign serve so the completion signal reaches their trigger injectors.
fork_token_envstringoptionalEnv-var NAME holding a git credential (PAT/token) used to authenticate git fetch &lt;cloneUrl&gt; for fork-PR ci-jobs (T-073 remainder — a fork of a private repo is itself private). Resolved through the secret chain (env → cuora → ~/.config/bupha/env), the same NAME-only rule as node_token_env: the value never lands in this config, in argv, or in the worker's env — the worker materializes a git credential-helper script (under the config dir) that re-resolves the NAME at fetch time, so only the fork fetch sees the credential. A fine-grained PAT that reads both the base org and the fork works here; fork creds that differ from origin creds get their own NAME. Absent = fork fetches ride whatever credential machinery the box already has (global credential helpers, url.insteadOf, gh auth setup-git) — public forks need nothing.

Constraints ​

  • queue = "all" rejects cancel_running = true at load — killing a run would silently drop a promised commit.
  • runner.kind and trigger.kind/status.kind resolve to impl crates; unknown kinds fail at bupha doctor/startup.
  • deny_unknown_fields: typos in field names fail the load.
