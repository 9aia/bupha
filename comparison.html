bupha vs hosted CI ​

bupha runs push-triggered CI on self-controlled hardware — not a GHA replacement at fleet scale.

vs GitHub Actions ​

buphaGitHub Actions
computeyour boxmanaged fleet
queuelatest-wins + bounded all, no cold startunlimited parallelism, queue wait
secretsnever leave the machinehosted on GitHub
cacheyour backend — local disk or your S3/R2/miniohosted cache
pipeline defyour runner — ci.sh or dagger moduleYAML DSL + marketplace actions
local == CIbupha run is literally the same pathact approximates
batchingsupersede built-in, honest "cancelled" statusesconcurrency groups
scaleone worker, serialized runsmatrix/fleet
costyour box onlyminutes billing

When GHA is better: you need parallelism, matrices across OSes, hosted macOS/Windows builds, or marketplace actions. When bupha fits: instant feedback on self-owned hardware, secrets that never leave the machine, warm caches on self-owned storage, no YAML.

vs others ​

  • Jenkins/Buildkite — bupha is a single binary with a TOML file, not a server product to operate.
  • Woodpecker/Forgejo CI — bupha is forge-webhook driven and much smaller; those are full pipeline platforms.
  • self-hosted GHA runner — bupha is lighter (no runner service, no org config) but has no matrix or marketplace.
