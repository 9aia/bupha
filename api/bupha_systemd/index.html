bupha-deploy — install-time helpers so users never copy files: bupha deploy service writes + enables the systemd unit, bupha deploy webhook registers the GitHub hook, and bupha deploy env seeds the secrets env file.

Structs§

SystemdService
systemd impl of the Service port.

Functions§

disable_service
Disable + remove the user unit. Best-effort stop first — an absent or never-enabled unit still gets its file removed.
enable_service
systemctl –user daemon-reload + enable –now. Needs loginctl enable-linger (once) to survive logout/boot.
restart_service
systemctl –user restart — bounce the watcher; enablement and the unit file are untouched.
service_logs
service logs — journal tail for the unit. follow hands the terminal to journalctl -f (inherited stdio) and returns its exit code; non-follow captures + prints the last 50 lines.
stop_service
systemctl –user disable –now — stop now, skip at login. Keeps the unit file so enable_service brings it back without a reinstall (unlike disable_service, which removes it).
unit_status
One-line “enabled= active=” for service status — is-enabled/is-active exit non-zero on disabled/inactive units, so failures report the state instead of throwing.
write_env_skeleton
Seed ~/.config/bupha/env with the secret names (empty values — never invent secrets). names is every env var the config resolves secrets from (global + per-repo + token).
write_service_unit
Render the user unit. unit is a systemd user service running bupha {verb} (“watch” for the listener, “worker” for a fleet puller); the watcher spawns the configured tunnel itself.
