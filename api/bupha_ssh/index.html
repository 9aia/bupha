Crate bupha_ssh 

Source
Expand description

SSH impl of Runner — ships the detached worktree to a remote host and runs the shell command there. Sync and run are separate stages (rsync first, ssh second) so an infra failure — unreachable host, rsync error — reports “ci infra: …” instead of a pipeline “ci failed”. The returned handle is a local process pair, so the worker’s wait/cancel logic is unchanged — the remote-ness lives inside the impl.

Config: [runner] kind = "ssh", remote = "u@h", remote_dir = "~/bupha", cmd = "./ci.sh" — auth via the user’s ssh config (agent/keys), nothing bupha-specific. Each run lands in its own remote dir <remote_dir>/<key>-<sha12> — two runners sharing a remote never rsync --delete each other’s tree.

The run script — including the resolved token_env value — is fed to the remote bash -s over ssh’s stdin, so the secret never appears in a remote (or local) ps listing.

Known caveats:

  • kill() terminates the local ssh and best-effort pkills the remote run shell (tagged argv0) + removes the run dir, but a remote process group that outlives its shell can still linger.
  • The rsynced worktree’s .git is a pointer file into the main clone’s gitdir — meaningless on the remote, so git commands inside the remote run fail. Pipelines that need VCS metadata must clone or init their own repo remotely.
  • The remote shell cleans its run dir after the command; a hard kill mid-run leaves cleanup to the pkill/rm -rf fallback.
