bupha-sturn — the sturn side of the trigger port. Reads refs/sturn/* straight out of a clone via git plumbing: the WAL is the state (sturn’s bus is only a cache), so polling refs is the robust ingest surface — it survives restarts, catches up after git fetch, and needs no daemon on the CI box.

What a CI-worthy event looks like: sturn snap appends an Op::Snapshot event commit to refs/sturn/wal/<ws> (each event is a commit whose tree holds event.json) and moves refs/sturn/ws/<ws> to the snap commit. The poller diffs WAL heads, walks new event commits, and turns Snapshot markers into (branch ref, sha, sender) pushes for the shared queue.

Sender attestation: actor in an event is self-asserted. When a signer policy exists (the repo’s sturn.toml [signing] allowed_signers, else ~/.config/sturn/allowed_signers) each event’s SSH signature is verified (ssh-keygen -Y verify, namespace sturn-event) — a signed event emits its actor, an unsigned or bad-sig event emits an empty sender (which [access] policies will deny). With no signer policy anywhere the sender is the bare actor claim — [access] kind = "all" compatible, but not an identity an allowlist should trust.

Structs§

Event

Meta
The sturn.toml knobs the poller needs. Missing file or missing fields fall back to sturn’s own defaults.
SturnSource
The sturn Source impl — polls each sturn = true repo’s clone for WAL movement (refs/sturn/wal/<ws>), reads new event commits, and on an Op::Snapshot marker emits the ws tip commit — the same queue every other source feeds. Polls refs, not the bus: the WAL is the state (the bus is a cache), so this needs no daemon and catches up across restarts via the persisted heads file.
