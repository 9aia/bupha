Remote execution over HTTP — HttpRunner ships a tarred worktree to a bupha agent and polls the remote job. Wire surface:

  • POST /jobs — {"key","sha","cmd","env_names":[..]} -> {"id"}.
  • PUT /jobs/{id}/worktree — raw tar bytes; the agent extracts under its own worktree.base and starts the run.
  • GET /jobs/{id} — {"status","desc"?} polled by try_wait.
  • DELETE /jobs/{id} — remote kill.

Every request is authenticated by X-Bupha-Auth: sha256=<hex> — an HMAC-SHA256 of the request body (same scheme as GitHub webhook signatures). Config carries the secret env NAME, never the value.

Caveats mirror bupha-ssh: a killed remote job can orphan the agent’s grandchildren (kill is best-effort), and tarred worktrees carry broken .git pointer files — remote runners must tolerate a non-functional .git.
