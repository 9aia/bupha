Expand description

Resolves a uses: target that names an action directory — ./local/path or owner/repo[/sub/path]@ref — to the action’s action.yml text. plan stays I/O-free: the runner implements this (filesystem reads for ./, git fetch for remote refs); parse_workflow uses NoActions, which errors on any action uses:.

fn workflow_yaml(&self, _uses: &str) -> Result<(String, String, bool), String>

Resolve a jobs.<id>.uses: reusable-workflow target to (source-label, file text, is_remote). ./path reads the worktree; owner/repo[/path]@ref fetches like remote actions. is_remote marks callees fetched over git — a ./ call inside one can’t resolve against the caller’s worktree and is rejected. The default errors — parse_workflow has no resolver, so reusable calls fail loudly there.
