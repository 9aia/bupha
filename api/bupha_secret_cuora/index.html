Cuora impl of Secrets — the canonical secrets story (T-056). Thin wrapper over the shared [hypha_secret_cuora] adapter, pinned to the bupha scope.

Each bupha secret NAME resolves to a fixed cuora ref: cuora://bupha/<NAME> — e.g. BUPHA_WH_9AIA_BUPHA maps to cuora://bupha/BUPHA_WH_9AIA_BUPHA. Values are fetched through cuora so audit events, guardrails, and vault policy apply exactly as for every other consumer; bupha never stores a value itself.

Two transports, selected by BUPHA_CUORA_TRANSPORT (the <PRODUCT>_CUORA_TRANSPORT convention — see hypha-secret-cuora):

  • cli (default) — shell cuora get/put per call. Secret resolution happens a handful of times per run/verb, so a per-call process is cheap and needs no shared mutable state.
  • serve — a persistent cuora serve child speaking the ndjson JSON-RPC wire (cuora-serve/1) on stdio. Spawned lazily on first use, reused for the client’s lifetime.

A missing cuora binary, a denied op, or an absent ref all answer None — “not here” — so the caller’s chain falls through to the env-file leg exactly like a missing ref on a headless box, on either transport.

§Sealed-pack fallback (T-053)

The bupha scope is already the canonical fleet surface, so there is no middle scope here — but the CI-webhook secrets are migrating into the sealed tamias pack secrets-ci-webhooks (vault-less, age-sealed; see cuora’s cuora://<pack>/<secret> read path). Resolution is therefore a two-scope chain, vault first:

  1. cuora://bupha/<NAME> — the vault copy;
  2. cuora://secrets-ci-webhooks/<NAME> — the sealed pack;
  3. the caller’s next leg (env file).

Vault-first ordering means a name present in both keeps resolving to the vault value — packs are the migration target, not an override. set always writes the vault scope: pack contents are authored via tamias/cuora seal, never this store.

Env knobs: BUPHA_CUORA_BIN overrides the binary path (tests stub it); BUPHA_CUORA_TRANSPORT picks cli/serve; CUORA_* and --config resolution stay cuora’s own — the child inherits the environment, so CUORA_ENV picks the vault env — bupha does not pin one.
