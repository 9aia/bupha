Architecture ​

bupha is a port/adapter monorepo: every external concern sits behind a trait (a port), and each integration is a crate that implements it (an impl). bupha-core is the pure domain — config shape, queue semantics, shared primitives — and depends on nothing outside itself; the binary is a thin composition root that wires impls to ports.

Request flow ​

POST /hook
  → 1. path check (404 otherwise)
  → 2. read body (≤ 2 MiB)
  → 3. signature verify (Trigger port — github impl: HMAC
       sha256, constant-time)
  → 4. dedup delivery id (bounded 10k ring; github impl uses
       X-GitHub-Delivery)
  → 5. parse — skip deletes/zero-sha; revision must be path-safe
  → 6. route — repository.full_name → watched [[repo]] entry;
       git_ref must equal repo.branch
  → 7. enqueue — per-repo queue; persist via QueueStore (redb,
       ACID)
  → 8. one global worker — Vcs fetch, detached worktree
       at <base>-<repo>-<sha12>
  → 9. spawn run handle (token via env:// name, never argv)
  → 10. status — pending → success/error; superseded and
        cancelled shas get honest error statuses

Queue semantics ​

policypendingon new pushuse for
latest (default)1 shasupersedes pending; cancel_running may kill in-flightCI gates
allbounded FIFO (32)appends; oldest evicted past cap; cancel_running rejected at load — it would drop a promised commitreleases

Persistence: accepted work writes through the QueueStore port (redb, single embedded file) inside worktree.base; on restart the interrupted running sha is re-queued at the front.

One global worker serializes runs across all repos — a second push queues behind the in-flight job. Deliberate (one box, bounded resource use), not a hang: journalctl --user -u bupha-watch shows the queue moving.

Security model ​

  • mandatory HMAC (constant-time compare) — unauthenticated payloads never reach the queue
  • body cap, delivery-id replay dedup, hex-sha validation before the value touches paths or status URLs
  • webhook takeover is exact-URL only; hook API calls are timed out
  • config names secrets (secret_env/token_env) — values resolve env → OS keyring → ~/.config/bupha/env (0600); the runner gets the token through its own mechanism (env:// for dagger)
